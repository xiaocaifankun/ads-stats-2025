# WorkflowVsAgent

[[Anthropic]] 在《Building Effective Agents》（2024-12-19）中给出的一条极窄判据，用来区分两类智能体系统：

> **下一步做什么，由代码写死，还是模型动态决定。**

这是**唯一**的架构分界线。以下都不构成区分依据：

- 是否调用了 LLM —— 两者都可调用；
- 是否接入工具与检索 —— 两者都可接入；
- 是否运行在沙箱 —— 与架构无关。

## 三层构件（自下而上）

```text
Agent 智能体
  控制流由模型动态决定 · 循环直至停止条件
─────────── 分界线：下一步由代码还是模型决定 ───────────
Workflow 工作流
  控制流写死在代码路径：提示链 · 路由 · 并行 · 编排 · 评估
─────────── 以上两层均构建于其上 ───────────
增强型 LLM
  检索 · 工具 · 记忆 —— 所有智能体系统的基本构件
```

## 判别示例

**客服工单系统**：先把工单分类（退款类走流程 A、咨询类走流程 B），每条流程的步骤完全写死在代码里。
→ 判为 **Workflow**（Anthropic 五种工作流中的「路由」模式）。**LLM 参与不等于 Agent**——它只在节点上干活，路径是写死的。

## 相关的三条原则

1. **先找最简方案，再谈 Agent**：很多场景优化单次 LLM 调用就已足够，甚至根本不需要智能体系统。Agent 用延迟与成本换任务表现。
2. **每一步都要拿到 ground truth**：否则错误随步数复利累积（同 [[ReAct]] 的 Observation）。
3. 自主性与复杂度递增——**按需选择层级**，不要默认跳到顶层。
