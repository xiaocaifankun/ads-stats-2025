### 结论一：这台机器当前**无法**用 SSH 推 GitHub（校园网整体封禁）

宏哥补充说明「校园网无法使用 ssh.github.com:443 的 SSH」，实测完整印证，并且比预期更彻底：

| 探测 | 结果 |
|---|---|
| `github.com:22` | 直连超时 |
| `ssh.github.com:443` 直连 | TCP 通，SSH 握手被 RST（`kex_exchange_identification: Connection reset`） |
| 会话代理 CONNECT `ssh.github.com:443` | 隧道 200 建立，**远端零字节后关闭** |

| 本机 19 个监听端口的 forward-proxy 能力扫描 | 无可用（9666/20101/18488/12900… 均非代理） |

### 结论三：网络事实的**两处更正**（旧 skill 里的条目已不成立）

1. **「清代理直连」不再可用**：实测 `github.com:443` 直连 TCP CLOSED；`env -u *_proxy git fetch` 报 `Failed to connect ... after 21104 ms`。**必须走会话代理**。旧的"三级降级链"（会话代理 → 清代理直连 → 10808）已失效。
2. **会话代理是间歇性 502，不是永久失效**：`CONNECT tunnel failed, response 502` 会自己恢复；同一条命令里 `gh api user` 成功而 `git fetch` 报 502 是常态。**必须写重试循环**，单次失败不能判定断网。`ls-remote`（小请求）能过不代表 `fetch`（带 packfile）能过。
3. 另两条旧记录已被本次实测推翻（如实并列，未静默取舍）：`refs/remotes/origin/*` **现已落盘**（`for-each-ref` 有输出、`rev-parse origin/main` 可解析）；`git rev-parse --abbrev-ref '@{upstream}'` 无上游时**报 fatal**，不是返回字面量。
