## 新建项目级 skill：`gh-push`（本地内容推送到 GitHub）

**位置**：`.workbuddy/skills/gh-push/SKILL.md`（项目级，非用户级）
**决策**：范围=全链路（add→commit→push）、认证=gh CLI 凭据、命名=`gh-push`。均已由用户确认。

**三条实测得出的硬事实（写进 skill，务必遵守）**

1. **`refs/remotes/origin/*` 在本机不落盘**（沙箱限制）。
   fetch 报 `* [new branch] main -> origin/main` 看似成功，但 `.git/refs/remotes/` 为空、`packed-refs` 不生成、`git for-each-ref refs/remotes` 为空。
   → 后果：`git rev-list HEAD...origin/main` 报 `fatal: ambiguous argument`；`--force-with-lease=main:<本地记录值>` 报 `stale info`。
   → **替代**：用 `git ls-remote origin refs/heads/<b>`（查远程真值）或 `FETCH_HEAD`（fetch 后立即读）。
   → **不要修**：`remote.origin.fetch` 配置本身正确（`+refs/heads/*:refs/remotes/origin/*`），问题在沙箱 ref 写入，改配置无效。

2. **静默认证必须两段式**：`git -c credential.helper= -c credential.helper='!gh auth git-credential' push ...`
   - 缺前半 `credential.helper=` → git 叠加，GCM 仍在链上，可能弹窗。
   - 写成 `credential.helper=''`（空串）→ 整链清空，报 `could not read Username ... terminal prompts disabled`。
   （实测 `gh auth git-credential` 静默返回凭据，无交互；gh 2.98.0，账号 yangjh-xbmu，scopes 含 repo/workflow。）

3. **`@{upstream}` 判定假阳性**：无上游时 `git rev-parse --abbrev-ref '@{upstream}'` 返回字面量而非报错，`||` 兜底失效。→ 改用 `git config --get branch.<b>.merge`。

**其他记入 skill 的内容**：代理三级降级链（会话代理会 502 → 清代理直连 → 10832 静态代理）；推后必用哈希比对验证（不信退出码）；强推必须带真实远程哈希的 lease 且先确认。

**验证**：skill 用自己推了自己 —— 提交 `.workbuddy/skills/gh-push/SKILL.md`，`9cc85d0..8940a90 main -> main`，本地/远程哈希一致，工作区干净，全程零弹窗。
