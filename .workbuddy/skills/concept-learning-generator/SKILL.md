# 概念学习资料生成器 (Concept Learning Material Generator)

本 Skill 的目标：把一个"概念"变成一个**可学习、可复核、可复用**的结构化资料，而不是一段 AI 聊天记录。
它适用于课程学习、读书笔记、技术调研、新人 onboarding 等任何"我要搞懂 X"的场景。

---

## 一、适用场景 (When to use)

- 用户说"帮我学习 / 搞懂 / 整理 / 出一份资料 关于 <概念>"。
- 用户在做某个主题的调研，需要把零散信息收敛成一份带来源的笔记。
- 用户需要为团队或课程产出可复用的概念说明（如 Agent、上下文、Skill、RAG……）。
- **不适用**：纯代码实现、纯文本翻译、一次性问答（这些用普通对话即可）。

触发判断：若用户给的是一个**名词/概念/术语**，且期待一份"资料"而非一句话答案，则使用本 Skill。

---

## 二、输入信息 (Input)

调用时尽量收集以下信息（缺省项可合理假设，但要在生成物中标注"假设"）：

1. **概念名称**（必填）：如 `Agent`、`大模型的上下文`、`Skill`。
2. **学习视角 / 背景**（可选）：如"从 AI Agent 工程角度""面向大三学生""用于面试复习"。
3. **目标产出格式**（可选，默认 HTML）：`html`（默认，独立可打开）、`md`。
4. **输出路径**（可选，默认 `learning-materials/<slug>.html`，slug 为概念英文/拼音短名）。
5. **已有偏好**（可选）：配色、语言（默认中文）、是否要可视化讲解、偏好哪类图（默认由模型判断概念难点后自行决定）。

---

## 三、生成步骤 (Procedure)

> 核心理念：**先找真实来源，再写自己的话。禁止凭空编造引用链接。**

### Step 1 — 拆解与检索 (Research first)

**来源红线（硬性，违反即返工）**：检索时**必须**排除低可信聚合类站点，必要时对结果做域名过滤：

- **禁止采信**（不可作为"参考来源"写入，也不可作为事实依据）：
  - 各类**文库类**站点：百度文库、豆丁、道客巴巴、原创力文档等；
  - 各类**百科类**站点：百度百科、维基百科、MBA 智库百科、搜狗百科等；
  - 各类 **AI 知识库 / 笔记聚合分享页**：如 `ima.qq.com` 及其 `wiki` 分享页、Notion 公开页、语雀/飞书公开分享页等**用户自建的二手笔记**；
  - 各类**内容农场、CSDN 洗稿文、公众号拼贴、知乎/小红书个人总结**（除非作者即原始作者本人且文中给出原创出处）。
- **为什么**：这类内容**无法溯源、常被二手转述失真、版本信息缺失**。用于学习卡片会产出"看起来有理、其实无据"的内容。
- **正确做法**：直奔**一手来源**（优先级见下），并在查询词中叠加限定（如 `site:docs.xxx.com`）。很多官方文档站的页面链接直接写在 HTML 里，可先抓取**导航目录**列出全部页面，再定位目标页。

**权威来源优先顺序**：
1. **官方文档** / 官方帮助中心 / 官方工程博客（首选，尤其当概念属于某个具体产品时）。
2. **官方发布说明** / Changelog / 官方 SDK 与 API 参考。
3. **经典论文**（arXiv 等，如 Attention Is All You Need）。
4. 领域公认的**原创**技术博客 / 综述（如 Lilian Weng 的 Lil'Log、厂商官方技术博客）。
5. 课程 / 教科书（仅作辅助，不单独作为主来源）。

**必做的两件事**：

- **抓取而非回忆**：来源内容必须**实际抓取**（`WebFetch` / `curl`）后写入，不得凭模型记忆复述。
- **本地证据核对**：若概念涉及**本机或本项目实际产物**（某个产品的文件、目录、配置、界面），务必到**本机实际查看**，用真实存在的路径/文件内容作为证据，并在文中注明"本机实测"。**不要**把官方文档描述的机制与本地文件的形态混为一谈——两者可能不是同一套东西。

记录每条来源的**真实 URL 与标题**，稍后原样写入"参考来源"。若概念太新或来源稀少，明确标注"公开可靠来源有限，以下为基于既有资料的推论"。

### Step 2 — 结构化组织 (Organize)
按下面的"输出结构"把内容组织成 **9 个板块**（其中"可视化讲解"是专门用来图形化核心概念 / 难点的模块，规则见"四、输出结构"）。每个板块都要用自己的话写，**不得整段照搬任何来源或 AI 对话原文**；引用处用 `[来源 N]` 标注。

### Step 3 — 撰写个人解释 (Personalize)
"个人解释"板块必须以**第一人称**写，体现学习者自己的理解（"我理解它其实是……""它和 Y 最大的不同是……"）。这部分可由 AI 起草，但应留出供本人修改的空位或明显标注，便于人工复核。

### Step 4 — 生成文件 (Generate)
- 生成独立 HTML：内联 CSS（不依赖外部样式表，便于直接双击打开），使用清晰的卡片/分区布局，浅色主题，中文排版。
- 顶部放概念名、一句话定义、生成日期。
- "参考来源"用 `<ol>` 列出，每条含**可点击真实链接**与一句话说明。
- 生成"可视化讲解"板块：按该模块的"选型"规则，为**最适合**用图讲核心概念 / 难点的 1–3 处画图。优先用**纯 HTML + 共享/内联 CSS**（div 条、进度条、表格、网格、内联 SVG，离线双击即可看）；需要复杂拓扑时才引入 Mermaid（CDN `https://cdn.jsdelivr.net/npm/mermaid`）。**每张图都必须有图说文字兜底**，防止离线 / CDN 失效时读者看不懂图。

### Step 5 — 自检 (Self-check)
执行下方"自检要求"清单；不通过则修正后再交付。

## 四、输出结构 (Output structure)

每份资料必须包含以下板块（HTML 中的 `<section>`）：

1. **学习目标** — 学完这份资料后，应能回答/做到什么（3 条左右）。
2. **核心问题** — 围绕该概念最该搞清楚的 2–4 个问题。
3. **个人解释** — 第一人称、用自己的话概括"它到底是什么"。
4. **核心机制 / 组成** — 它由哪些部分构成、如何运作（可用列表/图示）。
5. **可视化讲解（Visualize）** — 用图形化的方式呈现"文字讲不清、图一看就懂"的核心概念 / 难点 / 易混淆点。这是本 Skill 的专属讲解模块，具体规则见下方「可视化讲解模块」。全篇图表控制在 **1–3 张**，宁缺毋滥。

   **可视化讲解模块（务必遵循）**：
   - **触发判断**：只有当模型判断"该点存在 结构 / 流程 / 对比 / 定量 / 时空 维度，且比纯文字更利于理解"时才画。核心概念、难点、易混淆点里"值得画"的就画；文字能说清的**不必硬凑**。
   - **选型（按内容选最合适的，可混用）**：组成/结构→结构图·分区/堆叠条；流程/步骤·生命周期→流程图·箭头链·时间线；大小/占比/对比→条形·进度·仪表盘·数轴；概念间关系（依赖/因果/包含）→关系图（节点+连线）；连续变化/分布/陷阱→曲线·区间轴（如 位置→利用率）。
   - **实现（必须离线可打开）**：默认**纯 HTML + CSS**（不依赖外部资源，双击即可看）；拓扑复杂时才用 Mermaid（CDN）。**禁止**只用一张外链图片或 base64 大图充当"可视化"（加载慢、不可控、无离线兜底）。
   - **文字兜底（强制）**：每张图配 `class="viz-caption"` 的**一句话图说**；若图依赖 Mermaid / JS / 外链，**必须再附一行纯文字说明**，保证离线 / CDN 失效时读者仍能从文字看懂"这张图在说什么"。
   - **数据诚实**：图中出现的数字/占比/坐标必须**真实可溯源**（对应正文或 `[来源 N]`）；示意性数字显式标注"约/示意"，不得把臆造数值当事实。
   - **可交互（可选加分项）**：对阈值/滑块/展开等可用轻量原生 JS（如 `<input type="range">` + 内联脚本），不依赖框架；无交互也完全合格。
   - **落位**：紧跟在"核心机制"对应讲解之后，作为独立 `<section>`，编号连续。

6. **应用场景** — 一个**具体**的例子（说明谁、在什么环节、用它解决了什么）。
7. **易混淆 / 使用边界** — 常与什么概念搞混、什么情况下不适用或会失效。
8. **自测问题** — 3–5 道简答题/选择题，附答案或答题要点（折叠或置于文末）。

   **自测题出题规范（务必遵循，确保可真正用于自我测验）**：
   - **题型组合**：3–5 道简答题 + 1–2 道选择题 + 1–2 道应用题（"请描述 / 举例"类）。
   - **覆盖维度**：①概念辨析（与易混概念的区别）；②核心机制（组成 / 运作）；③具体应用场景；④风险与边界（何时失效 / 常见失败模式）。
   - **答案格式**：每题配答案或答题要点；选择题给出正确选项并简述理由；答案置于 `<details>` 折叠区，便于先自测再看；应用题给"答题要点"而非唯一标准答案。
   - **语言**：题干与答案用中文，可保留英文术语（如 Planning / Tool Use / Workflow）。

9. **参考来源** — 真实、可核查的链接列表，带编号。

## 五、资料来源要求 (Source requirements)

- **禁止伪造**：不得编造 URL、论文编号、作者或"据说某大厂说过"。
- **禁止采信二手聚合与百科类内容**：文库、百科、AI 知识库分享页、内容农场等（详见 Step 1 来源红线）。学习卡片的价值来自**一手来源 + 自己的话**；一旦引用二手转述，卡片就失去了可核查性。
- **可核查**：每条来源必须是真实存在、可点击、内容相关的链接；**必须实际抓取过**（`WebFetch` / `curl`）。不确定是否仍有效时先验证；返回 404 的直接弃用，不得保留。
- **主来源优先官方**：概念的解释以官方文档/论文为准，博客仅作补充与通俗化。
- **本地证据优先**：当概念涉及本机/本项目实物的形态（文件、目录、配置、界面），以**本机实测**为准并在文中标注；官方描述与本地实际不一致时，**明确区分并说明**（官方口径 ≠ 本机形态）。
- **标注引用**：正文中用 `[来源 N]` 对应"参考来源"列表，便于回溯。
- **区分事实与观点**：官方事实、他人观点、本人理解要分开写，不混为一谈。

## 六、自检要求 (Self-check before delivery)

交付前逐条确认，全部为"是"方可提交：

- [ ] 概念名称明确，且资料确实围绕该概念展开？
- [ ] 9 个板块齐全（目标/问题/解释/机制/**可视化讲解**/场景/边界/自测/来源）？
- [ ] "个人解释"是第一人称、非照搬来源？
- [ ] **所有来源均为官方文档 / 论文 / 一手资料，无文库、百科、AI 知识库分享页等二手聚合内容？**
- [ ] 所有参考链接都是**真实可点击**的（未伪造、未 404、且已实际抓取）？
- [ ] 没有整段复制 AI 对话或某一来源原文？
- [ ] 涉及本机/本项目实物的部分，是否已用**本机实测证据**核对，并区分了"官方描述"与"本机形态"？
- [ ] 应用场景是具体例子，而非空泛描述？
- [ ] "自测问题"含题型组合（简答/选择/应用）且覆盖概念辨析、机制、应用、风险四维度？
- [ ] HTML 可独立打开、无明显排版错乱？
- [ ] 若使用了 Mermaid 图，有文字说明兜底？
- [ ] "可视化讲解"板块：是否为"适合可视化"的核心概念/难点画了 1–3 张图？每张图是否都有**文字/图说兜底**（离线也能看懂），图中数字是否**真实可溯源**或已标注"示意"？

## 七、示例调用 (Example invocations)

- "用 concept-learning-generator 学习一下 Agent，做成 HTML 放到 learning-materials/agent.html"
- "帮我生成'大模型的上下文'的学习资料，视角是 AI Agent 工程，输出中文 HTML"
- "我想搞懂 Skill 在 AI Agent 里是什么，给我一份带来源的学习卡片"

> 注意：本 Skill 面向任意概念，不要把它写成只服务于 Agent / 上下文 / Skill 三个概念的一次性提示词。新增概念时，只需提供概念名，重复 Step 1–5 即可。
