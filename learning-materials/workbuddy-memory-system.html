概念学习卡片 / Concept Learning Card

WorkBuddy 记忆系统 WorkBuddy Memory System — 官方口径的「记忆」到底是什么，它和本地文件是什么关系

一句话定义：WorkBuddy 的「记忆」是一项从会话历史中自动提取个人信息的云端功能——
它由模型每晚整理成「记忆数据」，在后续对话中作为背景注入，让它越用越懂你。

生成日期 2026-09-10 来源 官方文档 4 篇（全部实际抓取） 本机实测 已核对文件形态

01学习目标

学完这份资料，你应该能够：

  1. 说清官方定义的「记忆」是什么。能讲明白它是从会话历史自动抽取的个人信息、按晚整理、以「记忆数据」形式注入后续对话，而不是简单地把聊天记录存下来。
  2. 分清「记忆」和本机那几个文件的关系。能区分官方产品功能层面的记忆（在设置里管理）与本地磁盘上的身份文件、工作记忆文件（在文件系统里管理）——这两件事经常被混为一谈。
  3. 掌握开关、查看、编辑、删除、导入这一整套操作。知道记忆在哪里管、怎么让它记住或忘掉一件事、以及依赖记忆做判断前为什么要先核验。

02核心问题

  1. 「记忆」到底记什么？——是从聊天里原样存记录，还是抽取成结论？抽取哪几类信息？
  2. 它什么时候更新、存在哪、谁能看见？——是实时写入还是定时整理？会不会被别人看到？
  3. 我能控制它吗？——能看、能改、能删、能关掉吗？关掉之后已经产生的影响能不能撤回？
  4. 「记忆」和本地那一堆 .md 文件是一回事吗？——如果不是，它们各自管什么？

03个人解释（第一人称）

说明：以下为本人的理解表述，用于自我复核；欢迎直接在原文上批注修改。

我理解 WorkBuddy 的记忆，本质上是一个「背景信息的自动供给系统」。模型本身没有记忆，它这次能"知道"什么，完全取决于开工前有没有人把背景递到它面前。记忆功能做的就是把这件事自动化：它从我的会话历史里挑出有参考价值的个人信息，抽成条目存起来，下次对话时自动塞进上下文。所以它不是"存聊天记录"，而是把流水提炼成结论。

让我觉得设计得比较克制的一点是它的更新节奏是"每晚整理"，不是实时写。我一开始以为说一句话就被立刻记下来了，但官方明确说的是"每晚整理当天会话"。这说明它是批处理式的：白天照常聊，夜里统一抽取。好处是不会在对话中途被写入动作打断，代价是当天说的事，当天不一定马上生效。

另一个让我修正了认知的点是「记忆」和本地那些 .md 文件不是同一套东西。我原先看到 ~/.workbuddy/ 下有一堆 Markdown 文件，就以为那就是"记忆系统的存储"。但核对官方文档后我发现：官方讲的「记忆」是一个产品功能，入口在"设置 → 记忆"里，可以在界面上查看和编辑；而磁盘上的 SOUL.md、USER.md 这类文件属于另一条线（身份与工作记忆），是文件形态的、可以直接用编辑器改的。官方文档里另外还提到项目级记忆文件 .codebuddy/CODEBUDDY.md，那是随代码库走、可提交到版本控制的团队知识——又是第三个层面。[来源 2]

所以我现在把它理解成三个层面：产品功能层的「记忆」（界面管理）、本地文件层的身份/工作记忆（文件管理）、项目层的团队知识文件（版本控制管理）。它们可以并存，但职责不同，混着讲就会自相矛盾。这也让我意识到：讲一个产品的机制时，官方口径和本机形态必须分开说，不能拿肉眼看到的文件去反推官方功能的设计。

04核心机制 / 组成

4.1 官方定义：记忆是什么

官方文档对「记忆」的定义很明确：记忆功能从你的会话历史中提取具有参考价值的个人信息（事实信息、偏好习惯、人物关系、近期跟进事项等），形成「记忆数据」并定期更新；后续对话或任务执行时，会将与当前请求相关的记忆作为背景信息一并参考。[来源 1]

这里有三层意思值得拆开看：

  • 来源是会话历史——不是让你手工填表，而是模型从日常对话里自己抽。
  • 抽取对象是"有参考价值的个人信息"——官方列举了四类：事实信息、偏好习惯、人物关系、近期跟进事项。
  • 使用方式是"注入上下文"——官方说明有两种用法：① 注入系统提示词作为上下文；② 支持对会话历史的检索（如问它"上周做过什么""之前聊过的 XX"）。[来源 1]

4.3 怎么管：查看 / 编辑 / 删除 / 导入

入口统一在头像 → 设置 → 记忆。[来源 1]

操作怎么做
查看 记忆摘要每晚重新生成；打开已生成的记忆即可查看内容。
编辑 点击右上角编辑图标，唤起对话框，用对话的方式告诉 WorkBuddy 要记住或忘记什么——不需要手动改任何文件。
删除 点击右上角删除图标，可清空当前记忆。
导入 支持同步你在其他 AI 上的使用习惯：点击「开始导入」，把官方给出的示例提示词复制到其他 AI 的对话中，再把结果粘贴回来，点击「添加到记忆」。
关闭 可一键关闭；关闭后将停止提取新的记忆。
实践要点：想让 WorkBuddy 记住某件事，最省事的做法不是去翻文件，而是直接在对话里说——例如"记住：这个项目的素材统一放 learning-materials/"。官方把"编辑记忆"设计成对话式，就是为了让你用自然语言完成这件事。

4.4 三个层面：记忆功能、本地文件、项目知识

这是本卡片最想厘清的一点。日常听到"WorkBuddy 的记忆"可能指三件不同的事，它们的管理方式完全不同：

① 记忆功能官方文档的「记忆」界面管理

③ 项目级记忆文件随代码库走版本控制
.codebuddy/CODEBUDDY.md ——官方定义为项目级记忆文件，存储项目架构、约定、常用命令等团队知识，可提交到版本控制并随项目共享给团队。[来源 2]
图说：同一个词「记忆」在三个层面出现：① 产品功能层的记忆，在设置界面里管，用对话方式编辑；② 本机磁盘上的身份/工作记忆文件，在文件系统里管，用编辑器直接改；③ 项目目录下的 .codebuddy/CODEBUDDY.md，随版本控制走，供团队共享。三者可并存、职责不同，混着讲会自相矛盾。注意：① 与 ② 的关系（是否同源、如何同步）官方文档未明确说明，本卡片不作推断。

为避免"把看到的文件当成官方机制的存储"，这里把本机实际核对到的情况原样列出（2026-09-10 实测）：

路径实测结果
~/.workbuddy/存在，含 SOUL.md、IDENTITY.md、USER.md、MEMORY.md、BOOTSTRAP.md、user-state.json 等。
~/.workbuddy/memory/存在，内含一份以 uid 命名的 *_memory.md（带 Version 号与 Last updated 时间戳，标题为「User Memory Profile」），另有 .bak 备份。这与官方所述"每晚整理、定期更新"的记忆数据形态吻合。
{workspace}/.workbuddy/memory/存在，当前含一份 2026-09-10.md（按日期命名的当日工作日志）。未发现同目录下的 MEMORY.md。
.codebuddy/（本项目）不存在。repos 下的其他仓库也均无该目录——说明项目级记忆文件需要按需创建，并非默认生成。

05应用场景

一个具体的例子——用 WorkBuddy 长期跟进一项课程建设：

假设你连续几周用 WorkBuddy 处理 ads-stats-2025 这个广告统计课程项目。记忆功能会在三个阶段发挥作用：

  1. 白天照常干活：你让它生成课件卡片、整理素材、修表格。过程中你提到过"这门课的素材放 learning-materials/""我偏好黑白灰加一个强调色""蓉蓉这个项目先放一放"。这些信息当下只是对话内容。
  2. 夜里自动整理：当晚，模型整理这些会话，抽取出其中有参考价值的个人信息——你的设计偏好属于"偏好习惯"，课程安排属于"近期跟进事项"。抽取由 WorkBuddy 自费完成，不消耗你的积分。[来源 1]
  3. 后续自动生效：过几天你新开一个任务，说"再出一份课程资料"。相关记忆被作为背景注入，它就知道你的配色偏好和输出目录，不用你再交代一遍。

过程中如果你发现某条记忆记错了（比如它以为你偏好的是另一种配色），不需要去翻文件——直接进「设置 → 记忆」点编辑，用对话告诉它"我不用那种配色，我要黑白灰加单一强调色"即可；想彻底重来就点删除清空。[来源 1]

这里有个细节值得注意：如果你在对话里直接问它"上周我们做过什么"，它支持对会话历史做检索。[来源 1] 这把"记忆"和"历史检索"连起来了——不仅能记住结论，还能按需翻回过程。

06易混淆 / 使用边界

最容易搞混的三组概念

容易混关键区别
记忆 vs 聊天记录 聊天记录是原始流水（说过什么就存什么）；记忆是模型抽取后的结论（事实、偏好、关系、跟进事项）。官方明确说是"提取具有参考价值的个人信息"，不是全量存档。[来源 1]
记忆功能 vs 本地记忆文件 前者是产品功能，在「设置 → 记忆」里查看编辑，用对话操作；后者是磁盘文件（如 ~/.workbuddy/MEMORY.md），用编辑器直接改。两者形态、入口、操作方式都不同。它们的同步关系官方未说明，不要自行推断。
个人记忆 vs 项目级记忆文件 个人记忆是你本人维度的、仅你可见；.codebuddy/CODEBUDDY.md 是项目维度的团队知识，可提交到版本控制、随项目共享给所有成员。前者跟着人走，后者跟着代码库走。[来源 2]

使用边界与注意事项

  • 依赖前先核验。官方明确提示：记忆由模型基于会话内容自动抽取，可能存在概括偏差或时效性问题，在依赖记忆做重要判断前建议先核验。[来源 1]
  • 关闭不等于撤回。关闭功能或删除记忆条目后，相应数据将停止用于后续对话，但已生成的输出不会因此追溯撤回。[来源 1]
  • 关闭后停止提取。一键关闭后将停止提取新的记忆；想恢复个性化就再打开。
  • 涉及他人信息要获授权。官方提示：会话中如涉及他人个人信息，请在提交前确认已获得相关授权。[来源 1]
  • 它不是知识库。记忆管的是"关于你这个人的信息"，与资料库（乐享知识库、腾讯文档等外部知识的检索）是两套东西，不要互相替代。

常见的失败模式

  • 把文件当功能：看到 .workbuddy/memory/ 下有文件，就断言"这就是官方记忆的存储"——把两条线混成一件事，结论会站不住。
  • 以为实时生效：白天说的事指望立刻被记住，但官方是按每晚整理，当天不一定马上生效。
  • 把过期信息当事实：记忆带有时效性风险，长期不清理可能让旧偏好持续影响新任务。
  • 指望删除能追溯：删掉记忆不等于已经产出的内容会消失，涉及敏感内容需要另行处理。
