# Agent 记忆系统

**把经验存到上下文窗口之外，并在需要时精准取回的机制。**一句话：记忆本质上是**检索问题**，不是存储问题——存了取不回，等于没存。
检索 = 新近度 + 重要性 + 相关性 分层：小而快的上下文 + 大而慢的外部存储 WorkBuddy 三层：云端 · 用户级 · 工作空间
## 01它是什么

**LLM 天生失忆：参数里没有你的对话，上下文窗口装不下你的历史。**记忆系统的使命，就是让每次会话结束时经验不蒸发，下一次按需取回。


LLM 每次调用都是无状态的：所谓「记住」，全靠系统在 prompt 里重新喂入内容。记忆系统 = 外部存储 + 取回机制。

## 03运行全程 · 四步循环

**任何记忆系统都在跑同一个循环：写入 → 蒸馏 → 检索 → 注入。**会话结束，新经历再次写入，如此往复。

<!-- 图 -->

```text
① 写入
追加原始记录
append-only
② 蒸馏
压缩提炼要点
反思 / 摘要 / 归档
③ 检索
按打分取 top 项
向量 / 关键词 / 时间
④ 注入
放进当前 prompt
成为上下文
新经历 · 回到写入，循环往复
图 3 · 记忆生命周期：只存不馏会膨胀，只馏不检会失焦
```

蒸馏是「聪明的遗忘」：Generative Agents 用反思把琐碎观察合成高层洞见，Anthropic 用 compaction 把长对话压成摘要——只存不用，迟早淹没在噪声里。
## 04WorkBuddy 的记忆设计

**WorkBuddy 按「作用域」把记忆切成三层：云端画像管「你是谁」，用户级文件管「你的偏好」，工作空间日志管「这个项目发生了什么」。**

检索策略按层分化：云端靠服务端排序（历史对话检索），本地靠「会话启动注入 + 按需读文件」。写入则克制——明确要求「记住」才落盘，项目日志在实质性工作后追加。
## 05铁律

- **记忆是检索问题，不是存储问题**存了取不回等于没存；检索打分（新近度·重要性·相关性）决定记忆质量。
- **分层是唯一出路**小而快的上下文 + 大而慢的外部存储，在两者之间换入换出——MemGPT 的虚拟内存思想。
- **必须会遗忘**追加式日志必须配蒸馏/压缩，否则旧记忆的噪声淹没新任务的信号。
- **作用域决定归属**用户偏好放用户级，项目约定放工作空间级，长期画像归服务端——放错层就会「换个项目就失忆」。
- **显式记忆优于静默记忆**明确说「记住」才写入：可控、可审计、可清理；静默自学习容易记住错的且删不掉。

### 第 1 题（基础 · 识别）

记忆系统要解决的根本问题是什么？
- A. 模型参数量不足，需要外挂存储补齐
- B. 上下文窗口有限，且会话结束即失忆 ✅
- C. 模型推理速度太慢，需要缓存加速
- D. 工具调用不稳定，需要日志回放

**解析**：LLM 本身无状态、窗口有限。记忆把经验外置到上下文之外，新会话按需取回。

### 第 2 题（基础 · 识别）

Generative Agents 的检索打分由哪三个因子组成？
- A. 速度 · 精度 · 召回
- B. 频率 · 时间 · 字数
- C. 新近度 · 重要性 · 相关性 ✅

### 第 3 题（进阶 · 理解）

关于 MemGPT 的分层设计，正确的说法是？
- A. 把全部历史对话塞进上下文窗口
- B. 上下文满了就随机丢弃最旧的对话
- C. 归档库只存向量，不存原文
- D. 主上下文放当前相关内容，外部检索库与归档库按需换入换出 ✅

**解析**：OS 虚拟内存思想：内存（主上下文）不够，就在内存与磁盘（外部存储）之间换页。归档库存完整原文。

WorkBuddy 的云端画像为什么「本地改不动」？

### 第 5 题（挑战 · 应用）

- B. 需要重新注册账号才能找回记忆
- C. 云端画像损坏，必须重置全部记忆
- D. 项目约定存在工作空间级 MEMORY.md，是本地文件；把项目的 .workbuddy/memory/ 随项目迁移，或重述一遍关键约定 ✅

### 第 6 题（挑战 · 应用）

记忆越积越多，AI 开始答非所问、注意力涣散。依据记忆系统设计原理，应如何治理？
- A. 换一个上下文窗口更大的模型
- B. 彻底停用所有记忆功能
- C. 蒸馏压缩：旧日志按主题提炼进长期记忆后清理，控制活跃条数，保留高信号 ✅

**解析**：四步循环中「蒸馏」就是聪明的遗忘——Generative Agents 的反思、Anthropic 的 compaction、WorkBuddy 的 30 天蒸馏，都是同一个原理。导出而不清理，噪声仍在原处。
