Agent 记忆系统

把经验存到上下文窗口之外，并在需要时精准取回的机制。一句话：记忆本质上是检索问题，不是存储问题——存了取不回，等于没存。

检索 = 新近度 + 重要性 + 相关性 分层：小而快的上下文 + 大而慢的外部存储 WorkBuddy 三层：云端 · 用户级 · 工作空间

01它是什么

LLM 天生失忆：参数里没有你的对话，上下文窗口装不下你的历史。记忆系统的使命，就是让每次会话结束时经验不蒸发，下一次按需取回。

LLM 每次调用都是无状态的：所谓「记住」，全靠系统在 prompt 里重新喂入内容。记忆系统 = 外部存储 + 取回机制。

02核心设计 · 三大通用范式

业界收敛出三种范式：像日记本一样打分检索（记忆流），像操作系统一样分层换页（MemGPT），像文件柜一样读写文件（Memory Tool）。

三者不互斥：现代产品通常混用——文件做载体，打分做检索，分层做容量管理。

03运行全程 · 四步循环

任何记忆系统都在跑同一个循环：写入 → 蒸馏 → 检索 → 注入。会话结束，新经历再次写入，如此往复。

蒸馏是「聪明的遗忘」：Generative Agents 用反思把琐碎观察合成高层洞见，Anthropic 用 compaction 把长对话压成摘要——只存不用，迟早淹没在噪声里。

04WorkBuddy 的记忆设计

WorkBuddy 按「作用域」把记忆切成三层：云端画像管「你是谁」，用户级文件管「你的偏好」，工作空间日志管「这个项目发生了什么」。

检索策略按层分化：云端靠服务端排序（历史对话检索），本地靠「会话启动注入 + 按需读文件」。写入则克制——明确要求「记住」才落盘，项目日志在实质性工作后追加。

05铁律

  1. 记忆是检索问题，不是存储问题存了取不回等于没存；检索打分（新近度·重要性·相关性）决定记忆质量。
  2. 分层是唯一出路小而快的上下文 + 大而慢的外部存储，在两者之间换入换出——MemGPT 的虚拟内存思想。
  3. 必须会遗忘追加式日志必须配蒸馏/压缩，否则旧记忆的噪声淹没新任务的信号。
  4. 作用域决定归属用户偏好放用户级，项目约定放工作空间级，长期画像归服务端——放错层就会「换个项目就失忆」。
  5. 显式记忆优于静默记忆明确说「记住」才写入：可控、可审计、可清理；静默自学习容易记住错的且删不掉。
